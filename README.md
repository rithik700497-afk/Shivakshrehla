# Royal Feast — native app (Flutter)

A real native app (not a website wrapper) for the Royal Feast ordering system. It talks to the **same server** as the website
(`/api/restaurant/api/*`), so menu, prices, offers, store open/closed, orders, wallet and kitchen/owner alerts all stay in one place.

## What the app does
Menu (search, veg filter, categories, banners, offers, open/closed) · cart saved on the phone · OTP login · delivery addresses ·
coupons · delivery / takeaway · pay with **Razorpay**, **cash on delivery** or **wallet** · live order tracking · order history ·
profile, wallet balance, account deletion · **FCM push** (order status, tap opens the order) · branded **No Internet Connection** screen with server health check.

**Not in this first version:** Scratch & Win / loyalty stamps, dine-in QR ordering, Google sign-in, and the owner/admin dashboard (owners keep using the website admin).
The API for loyalty exists (`/api/loyalty/*`), so it can be added as the next module.

## Setup (PC with Flutter 3.27+ and Android Studio)
1. **Create the Android/iOS folders** (they are not in this zip because they are generated by Flutter):
   ```
   cd royal_feast_app
   flutter create --org com.yourcompany --project-name royal_feast_app --platforms android,ios .
   ```
   Afterwards check that `lib/main.dart` is still the Royal Feast one (not the counter demo) and delete `test/widget_test.dart` if Flutter added it.
2. **Android manifest** — open `android/app/src/main/AndroidManifest.xml` and add before `<application>`:
   ```xml
   <uses-permission android:name="android.permission.INTERNET"/>
   <uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
   ```
   (Flutter only adds INTERNET to *debug* builds — without this line the release app cannot reach your server.)
3. **Firebase / push** (use the same Firebase project as the website):
   ```
   dart pub global activate flutterfire_cli
   flutterfire configure        # replaces lib/firebase_options.dart, adds google-services.json, patches Gradle
   ```
   Make sure the Android package name you pick matches `--org` + project name above (`com.yourcompany.royal_feast_app`) or whatever you set in Firebase.
   On the server, finish `FCM.md` (service account in `.env`). Without Firebase the app still works, just without notifications.
4. **Deploy the server changes** from `royal-feast/` in this zip first. The only change the app needs is in
   `app/api/restaurant/api/customers/auth/otp/verify/route.ts` (returns the session token to the app when it sends `x-rf-client: app`).
5. **Run on a phone** (USB debugging on):
   ```
   flutter pub get
   flutter run --dart-define=API_BASE=https://order.yourdomain.com
   ```
   Test: menu loads → OTP login → add dishes → place order → pay with Razorpay **test** keys / COD → tracking screen → notification arrives when the kitchen changes the status.
6. **Release**
   ```
   flutter build appbundle --release --dart-define=API_BASE=https://order.yourdomain.com
   ```
   Create a keystore and `android/key.properties` as in Flutter's "Build and release an Android app" guide. **Keep the keystore and passwords forever.**
   Set the app name/icon (`android/app/src/main/res/mipmap-*`, e.g. with the `flutter_launcher_icons` package and `assets/icon.png`), then upload the `.aab` to Play Console.
   Play listing checklist (privacy URL `/order/privacy`, account deletion URL `/order/delete-account`, data-safety form) is the same as `royal-feast/PLAYSTORE.md`.

## iOS (needs a Mac)
`flutter create` makes `ios/`. In Xcode enable **Push Notifications** + **Background Modes → Remote notifications**, upload an **APNs key** in Firebase (Project settings → Cloud Messaging), and run `cd ios && pod install`.

## How it is organised
```
lib/config.dart        server address (--dart-define=API_BASE)
lib/core/api.dart      HTTP client + Bearer token + error handling
lib/core/session.dart  login state (token in secure storage)
lib/core/push.dart     Firebase Cloud Messaging
lib/state/*            cart (saved on phone), menu/store status
lib/screens/*          home, cart, payment, orders+tracking, addresses, profile, login, offline
lib/router.dart        screens + bottom tabs + notification deep links
test/cart_test.dart    cart rules
```

## Honest notes
- This code was written without a Flutter SDK available, so it has **not been compiled or run yet**. Expect a few small fixes on the first `flutter run`
  (mostly package-version differences); `flutter analyze` will point at each one. The server side was checked against the real routes in the project.
- Prices are always re-checked by the server. The app never decides what you pay.
- If the order-status names on your kitchen board differ from `PLACED/ACCEPTED/PREPARING/READY/COMPLETED`, adjust `_steps` in `lib/screens/orders.dart`.
